
**Input manifest (required fields).** Package identity + issue timestamp + issuing surface; model/tool/surface provenance; scope declaration (namespaces covered); authority map — for each covered (namespace, scope, subject): current AC7 version, creating AC6 ref, pinned imports with versions; currentness/staleness stamps per projected source; current-state projection (from AC8); completed actions; pending actions; forbidden actions (from operative records and standing boundaries); one-safe-next-action; unknowns and unsupported assumptions (explicitly listed, UA-referenced where applicable); answered-question index refs (AC6/AC5 pointers) supporting the no-re-asking rule; evidence-path fields (resolvable refs, never inlined originals); package-tier slot: minimum | standard | extended — content per tier is a slot only, MC-02's tier proposal not adopted; trigger parameter slot recording which DP13 trigger fired — trigger value not chosen here.

**Generation procedure.** Verify source resolvability → assemble fields in manifest order → T field-completeness and pin checks → stamp staleness → journal issue entry → deliver via the profile's handoff method.

**Consumption procedure (ordered recovery sequence).** (1) verify package identity/integrity; (2) recover the authority map and check each entry against AC6 chain refs; (3) recover currentness/staleness stamps — stale entries are flagged, not trusted; (4) load working-state projection as rebuildable convenience; (5) load completed/pending/forbidden actions; (6) register unknowns and unsupported assumptions as open, not resolved; (7) resolve evidence paths on demand; (8) apply the no-re-asking rule — before asking H anything, consult the answered-question index; an authorized answer that exists is used, not re-asked; (9) echo: consumer restates scope, authority map, forbidden actions, and the one safe next action; (10) H confirms any authority-affecting continuation; (11) execute only the one safe next action until confirmation.

**Successful recovery criteria.** Identity verified; authority map complete and AC6-backed; no authority minted; staleness explicit; unknowns preserved; forbidden actions honored; echo matches manifest; no answered question re-asked; H confirmation obtained where required.

**Failed-handoff handling.** Any criterion unmet → halt continuation, journal the failure, fall back to source artifacts, regenerate the package; the failed package is retained, marked failed. **Old-package status.** Prior packages are historical R5 records — examples, never current truth (UA-02); consuming an old package requires fresh staleness resolution.

**Correctness checklist (design-level only).** identity_verified; authority_map_complete_and_decision_backed; no_authority_minted; staleness_stamped; unknowns_explicit; forbidden_actions_listed; one_safe_next_action_present; no_reasked_answered_question; evidence_paths_resolvable; provenance_recorded; tier_and_trigger_slots_populated_as_parameters. No numeric weights, verdict thresholds, or token ranges from candidate instruments are adopted.

## 13. Validation-stage design
