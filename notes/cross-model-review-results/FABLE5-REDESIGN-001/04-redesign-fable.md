## 1. 设计目标（对登记表负责的翻译）

以最少的 Owner 负担，让**任何一代模型的任何一个新会话**在数分钟内变成"像是同一个对话的延续"（N-01 双指标运营化），同时让 Owner 的每一句话被逐字保存、有依据地采纳、可被将来更强的模型重新兑现（N-02/03/05/14），并把这套做法沉淀为其他 agent 可直接套用的经验（N-11/17）。

## 2. 架构总览：三面五层（默认抽象下的组织；028 并入点）

**三面**（N-19 公理，系统级贯穿）：写入面尽量全（瓶颈只在可靠性）；读取面最小充分（分类默认不读）；呈现面人话（双频道）。

**五层**（按耐久性分层，落 N-15）：

| 层 | 内容 | 耐久性 | 毒性 |
|---|---|---|---|
| **L0 原始资料** | Owner 原话逐字件、反馈全材料、研究/对话原件（重件存 Alaya，仓库存收据） | **耐久核心**（append-only，永不改写） | 有毒——默认不读，仅生命周期处理与考古时按需 |
| **L1 裁决层** | Owner 裁决记录（准/改/驳/挂起＋原话）、supersession 边、澄清问答、验收标准 | **耐久核心**（真正的"资产"，N-14） | 无毒，低频读 |
| **L2 规范/现行层** | 迷你章程＋规范库（norms-library，见 §3）＋需求现行视图＋加载表 | **可再生**（由 L0+L1 重新编译；标注 built_for_model_generation） | 无毒，这是默认读取集 |
| **L3 工作层** | 各轨道工作区、检查点、交接包 | 任务生命期（任务结束转历史） | 对本任务无毒、对他任务有毒（N-19①） |
| **L4 派生索引** | 登记表、清单、摘要、（未来）检索索引 | **随时可重建**；每条带 source+hash 回链 | 无毒；铁律：索引坏≤降效率，永不改变谁是真相（023） |

模型迁移语义（N-03/05 落地）：换代＝**重编译 L2＋重评挂起队列**，L0/L1 原样继承；L2 文件头带 `built_for_model_generation`，新代模型上任首任务即触发 L2 复审（可行性重评走 §5 状态机）。

## 3. 规范库（norms-library）：从 13 份散文 guard 到条目化资产

现状问题（复盘诊断＋023/026 实证）：约束以数千行散文存在，常驻上下文过大反而降低遵循率；且历史证明"规则只增不减"。设计：

- **条目化**：每条规范一个稳定 ID（NORM-NNN），必填字段全内嵌（EXP-7 教训）：

```yaml
norm_id: NORM-001
statement: <一句话规则本体>
scope: <适用任务类型/路径>
status: active | superseded | retired | candidate    # 状态枚举完整内嵌
supersedes: []          # 显式取代边（022）
origin: <L1 裁决记录引用＋日期>
verification: <怎么算违反；能机械查的给检查方式>
compiled_check: none | script/hook/清单 引用          # 能编译的必须编译（N-19/026）
portability: mnemosyne_only | generic_candidate | generic_adopted   # N-17 迁移预留
built_for_model_generation: <代际标注>
```

- **复杂度预算**（反模式 #3 对冲）：常驻核心集目标 ≤200 行（023 遵循率证据）；norms 总量设整编触发（新增满 N 条或超预算即整编，减法与加法同权）。
- **归属与迁移**（N-17）：库整体自带索引与编号，作为可整体搬迁单元留在 Mnemosyne；Meta-Agent 成型后 lift-and-shift，旧址转引用＋备份，唯一权威源不变量由迁移清单机械校验。
- 现行 13 份 guard 的内容**不丢弃**：逐条映射进 norms（散文原件转 L0 历史），映射表机械可查（移码不移义）。

## 4. 三态循环的记录方案（原始资料→经检查构想→实现层）

对应 L0→L1→L2 的固定通道，每次流转留痕：

1. **捕获**（→L0）：Owner 任何输入 24h 内逐字入 raw（含上下文指针、日期、表面）；随手碎片走"最低摩擦入口"（发给任一在场 agent 即入 inbox——通道建设列需研究，02 §3）。
2. **检查**（L0→L1）：意图重建＋澄清三件套＋一致性/可行性分析（本轨道 X-1~X-4 流程即模板）；矛盾并列不调和，Owner 一字裁；裁决逐字回填。
3. **编译**（L1→L2）：裁决结果落为 norm/需求现行条目＋验收标准；能机械化的出 compiled_check。
4. **回流**：使用中反馈连材料入 L0（PF 记录即模板），触发新一轮检查。

## 5. 需求生命周期状态机（022 证据落地）

```text
captured(有毒) → clarified → analyzed(可行/需研究/不可行+替代)
   → adjudicated{准→compiled→in_use / 改→回clarified / 驳→archived / 挂起→deferred}
deferred: 必带 defer_reason ∈ {模型能力不足, Owner暂不要, 依赖未决, 成本} ＋ revisit_trigger
触发器: 新模型可用→deferred(能力类)批量进 review_needed 队列（不自动生效，Owner 消费节奏按 N-18 声明）
       矛盾检测→并列呈 Owner；周期测试→按 §8 锚点组；反馈→回流通道
in_use 条目变更: 只经新裁决＋supersession 边，禁止原地改写（ADR/RFC 模式）
```

状态枚举与必填字段随模板内嵌（EXP-7）；生命周期健康度按 022 §Q8 指标（可追溯完整率、过期误用率、复评及时率）年度抽测。

## 6. 加载/投影机制（记录≠加载的机械化）

- **任务型加载表**：每类会话（维护/设计/研究回收/交接接收/目标项目）一张编译好的读取清单（L2），次档模型照单执行不需懂原理（N-19 设计要求）；清单由强模型维护，变更走裁决。
- **常驻集**：迷你章程＋本任务加载表，目标 ≤200 行；其余全部触发式/按需（现行 loader 分层的证据化收紧）。
- **可观测**：每任务记录"应载/实载/漏载/误载"四单（023 污染度量），作为升级检索层的证据集。
- **升级阶梯**（023 结论照抄为策略）：人工分层＋rg（现在）→ manifest＋FTS5（当实测词汇错配持续出现）→ 本地向量 sidecar（当 FTS5 仍漏）→ 版本感知层（当"截至某时"类查询成高频）。**规模不触发升级，实测缺口才触发。**
- 投影铁律：一切派生视图带 source+hash 回链，可一键重建，失配即回退读原文。

## 7. 目的核查机制（与 fail-closed 同级的停止条件）

复盘根因（诊断 v2）："系统对权限冲突敏感、对目的漂移不敏感"。设计四件套：

1. **逐轮一行**：每次回复末尾"本轮对核心目标推进了什么"（已在本轨道运行）；答不出时必须写"零推进＋原因"。
2. **任务级字段**：每任务结果记录带 `purpose_delta`（对哪条 G 推进了什么/零推进）；机械可汇总。
3. **周期核查**：每主线按声明节奏（N-18）出一次目的账单：G 类推进 vs 治理开销占比；收尾记账类占比阈值 15%（校准值，反模式 #9）。
4. **停止条件**（同 fail-closed 级）：连续两个周期"零 G 推进＋纯治理"→ 主线自动 STOP，向 Owner 报"目的漂移警报"，未经一字批示不得继续该线工作。评分者偏差对冲：目的账单列入阶段 3 异族抽检范围＋Owner 随机抽查。

## 8. 交接方案（核心目标交付）与预冻结效果测试

### 8.1 交接协议 v2（三件套）

- **冻结工作态**：检查点文件（模板必填字段全内嵌）：

```yaml
checkpoint_id / date / mainline / declared_tempo(N-18)
goal_now: <一句话> / stage: <哪一门/哪一步>
decided: [已裁事项+裁决引用] / forbidden: [禁区] / open: [未决]
next_safe_action: <一步> / evidence_pointers: [五元恢复集所需最小指针]
hidden_dependencies: [不可从仓库重推的事实，逐条写明]   # DreamBench 教训
status_enum: active | consumed | stale | superseded
```

- **分层交接包**（Handoff Tax 证据）：按接收方选层——同代强模型接手：结构化摘要＋指针（默认）；弱模型接手：加完整轨迹；强模型接烂摊子：允许 fresh-restart＋仅要点。**反对教条全量**。
- **fail-closed 接收**：expected/observed 逐项表；缺关键字段/hash 不符/任务号不符→拒收；**anti-trap**：有明确 supersession 的"矛盾"应继续而非拒收（024）；接收报告回执后旧对话方可退役。

### 8.2 族间返场（本周实证补的空白）

任何一族离场超过阈值后回归：接收方先消费**追赶简报**（自动从 git log＋L1 裁决层生成 delta：期间裁了什么、冻了什么、编号/规范变了什么、在场写者与串行声明）；无简报不开工（fail-closed 同款）。同机多会话：worktree 分离（C-24 制度化）＋写者串行声明。

### 8.3 预冻结效果测试（024 低档方案选定）

- 样本：5~8 个真实历史检查点（S1/S2/S4/S7＋本轨道启动等），成对跑"新协议 vs 现协议"；
- 判分：全机械（五元恢复对照＋隐藏事实探针＋current/superseded 闭池）；LLM 只做不改结论的可读性备注；
- 对抗折：故意坏包（缺字段/伪 SHA/过期态）＋应接受的 anti-trap，分报真拒率/误拒率；折子先冻结后测试；
- 统计：配对呈现全部结果＋exact 检验；**n 小不谎称显著**（024 纪律）；
- 指标：Continuation Success、Rediscovery Overhead、Stale-State Error、Constraint Retention、Owner-touch 计数；体感线：Owner 盲抽"遮住边界看不出是两个对话"；
- 通过线（预冻结）：五元恢复全对率 ≥ 现协议；Owner-touch ≤2；对抗折误拒 =0 且真拒 ≥ 现协议。未过线不切换。

## 13. 自我批判与盲区

1. **同族偏置**：Claude 设计 Claude 遵守的规则，可能系统性高估自身执行风格的普适性——对冲：阶段 3 GPT-Pro 独立对照设计＋盲评（防火墙已设）；但对照结果仍需 Owner 裁，双族共盲区无人兜底。
2. **028 未回**：架构总览建立在被 Owner 定性为"想象成分很大"的默认抽象上；若 028 找到更优总体模型，§2~§6 需结构性修订（已留 v2 位）。
3. **压缩失义风险**：M2 的"移码不移义"靠映射表＋抽检，散文中的隐含语境可能在条目化中丢失——对冲：散文原件留 L0 永可回查；映射表列"未编译残余"栏。
4. **目的核查可被美化**：purpose_delta 由执行者自填——对冲：异族抽检＋Owner 抽查，但根上仍是自报制（诚实文化依赖）。
5. **预算数字多为校准值**（200 行、15%、≤2 触点）：首周期按实测重校，不当铁律。
6. **迁移成本未实测**：M1/M2 工作量估计粗糙；若超预期，允许按 N-18 声明慢节奏分批。
7. **本设计自身的复杂度**：五层三面＋状态机若执行走样，恰好重演反模式 #3——对冲：一切新机制先在本轨道自用一周期再进 norms（吃自家狗粮门槛）。

## 15. DR-028 并入修订（v1→v2）

028 复核结论：类比不必废弃，但五个"假保证"必须显式拆除；证据最一致方向是分层——**与本设计五层三面结构性合流**（L0+L1 即轻量"权威历史/账本"，L2/L4 即"可重建投影"，检查点即"应用级快照"）。据此三处强化：

1. **§2 抽象表述定稿**：顶层心智模型保留（"模型算、文件记"作导览语），但架构合同按修正语义书写——模型＝**可替换的概率语义计算后端**（换代须重验证）；上下文＝**从工作态编译出的有限注意力工作集**（≠可寻址内存；位置敏感为实证事实）；Git 文件＝耐久与可审计载体，"唯一真相"是**治理约定**（由 authority 规则与单向写入维持，非文件系统天然属性）；交接包＝**应用级检查点/再水化清单**（不承诺恢复模型内部状态）。五个假保证作为"禁止依赖清单"写入迷你章程。
