## 1. 命名格式

```text
[项目]-[主线]-[类型][序号] 简短主题
```

四段全部来自登记表（见 §3），示例：

| 名字 | 读法 |
|---|---|
| `MNE-M-C16 状态修复批次` | Mnemosyne · 维护主线 · 普通对话第 16 代 |
| `MNE-FR2-K01 第二轮评审` | Mnemosyne · FABLE5-REVIEW2 轨道 · Claude 网页对话第 1 代 |
| `MNE-M-DR14 学习者建模` | 维护主线委托的第 14 个深度研究 |
| `MA-B-W03 产品构建` | Meta-Agent · 构建主线 · Work 任务第 3 代 |

## 3. 三条铁律（针对档案盘点实证的四个陷阱）

1. **序号 = 主线内交接代数**，只在同主线交接时 +1；插队/派生对话用父名加后缀（`MNE-M-C16a`），不占代数——治"Depre-02 01 到底接谁"之乱；
2. **名字是导航元数据，不是权威**：canonical 任务号/轨道号仍以仓库记录为准；名字标错可随时改，不需要留痕仪式——治"改名残留前缀"之乱；
3. **不再用状态词命名**（Depre/Finish/Failed 一律不用）：对话的死活与成败写在归档索引里，不写在名字里——治"Finish-02 却在链条中段"之乱。日期不进名字（导出件自带创建时间）。

## 4. Claude 侧并入方式

- **Claude 网页对话**：创建时按 §1 起名（K 类型），与 ChatGPT 对话同一套登记；
- **Claude Code 会话**：不依赖手动命名——身份已由三层自动承载（轨道号入 commit 尾注、会话记录含逐条模型标识、转录归档自动带会话 ID）。需要 UI 辨识时用会话重命名功能打同格式标签即可，不强制；
- **归档衔接**：导出文件名 = 对话名 + 创建日期（现行惯例保留），族谱索引以任务号区间为准校验名字（本轨道已建立的方法固化）。

## 5. 登记表与迁移

- 主线码登记并入现有显示名注册表（新增一节：主线码 → 全称 → 状态），不建新文件；
- **历史对话不批量改名**（52+ 份既有导出的真实谱系已由归档索引承载，改名只会制造新混乱）；本规范自生效起用于新对话；
- Owner 手动起名负担评估：每次新对话约 10 秒（查表两段 + 类型 + 上代序号 +1）；忘了起名/起错名无惩罚，索引兜底。

## 6. 自我批判

- 序号依赖 Owner 记得上一代是几——错记会复制"系列号撞名"旧病；对冲靠索引校验（每次归档盘点自动核对），非防呆设计。更强的防呆（起名前查注册表）会把 10 秒变 1 分钟，判断为不值得 [MODEL_INFERENCE]；
- 类型码 K/CC 是新造约定，与业界无互通性——本就是私有体系，可接受；
- 派生对话后缀（16a）在派生再派生时会退化（16aa），赌的是这种深度极少发生；真发生时该反思的是工作结构而非命名法。
