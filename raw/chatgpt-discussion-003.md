# RAW-0003：Mnemosyne 第一批核心业务需求

这不是完整原始对话，而是从早期 ChatGPT 讨论中整理出的第三阶段交接记录，用于固化 Mnemosyne 的第一批核心业务需求。

## 1. Mnemosyne 的定位

Mnemosyne 是“记忆系统元 Agent”的工作仓库。

它不是某个具体项目的普通记忆库，而是一个用于设计、演化和交付外部持久记忆系统的元工作空间。

它未来要为不同场景设计记忆系统，例如：
- AI Agent 开发项目；
- 多 Agent 协作项目；
- 长期研究任务；
- 语言学习系统；
- 源码学习系统；
- 普通长期对话或个人知识管理场景。

Mnemosyne 的重点不是直接替具体项目“记住一切”，而是帮助具体项目建立合适的外部记忆结构、规则、handoff、归档、候选需求、实施版规范和后续演化机制。

## 2. 冯诺伊曼式外部记忆架构

Mnemosyne 采用类似冯诺伊曼计算机结构的工程类比：

- AI 模型相当于计算单元，只负责推理、总结、规划、生成和评估。
- 外部文件 / Git 仓库相当于长期存储。
- 提示词、规则、策略、工作流相当于程序或指令段。
- 需求、反馈、原文、项目状态、设计决策、证据、handoff 相当于数据段。
- 模型内部 memory 只作为缓存或辅助上下文，不作为长期真相源。
- 新旧对话之间的交接应依赖外部 handoff、active context 和实施版规范，而不是依赖模型自然记忆。

这个类比是工程抽象，不表示模型像传统 CPU 一样能确定性执行所有指令。关键状态必须外部化、可审查、可回滚。

## 3. 原文、候选需求和实施版必须分层

Mnemosyne 必须区分以下层次：

- Idea Capture Buffer：临时点子速记池，用于保存突然冒出的粗糙想法。当前只作为 TODO。
- Raw Archive：原文层，保存用户和上游 Agent 的原始输入、反馈、讨论或交接记录。
- Candidate Requirements：候选需求层，由模型从原文中整理出来，但不直接作为执行依据。
- Similarity / Conflict Notes：查重和冲突层，用于比较新想法和旧想法。
- Human-Approved Spec：人类确认实施版，是当前项目真正执行的依据。
- Active Context / Handoff：短上下文和交接层，帮助未来 AI 会话快速接手。

核心原则：
原文是证据，不是执行源。
模型摘要是派生视图，不是执行源。
候选需求不是执行源。
只有用户确认后的 Human-Approved Spec 才是执行源。

## 4. 新想法进入系统时必须查重和对比

用户可能在不同时期对同一问题提出相似但不完全相同的想法。
后提出的想法不一定比早期想法更好。

因此，Mnemosyne 在处理新需求或新反馈时，不能直接覆盖实施版，而应：

1. 保存原文；
2. 抽取候选需求；
3. 查找相同或相似的旧需求、旧想法、旧决策；
4. 比较相同点、差异、冲突和可能合并方式；
5. 向用户说明差异；
6. 让用户决定合并、替换、保留并列、拒绝或延期；
7. 只有用户确认后才更新 Human-Approved Spec。

当前阶段不实现自动查重，只记录该原则和未来 TODO。

## 5. 模型迁移需要专门流程

当一个项目从旧模型迁移到新模型时，不应简单地：
- 完全继承旧模型加工版；
- 或者从全部原文重新分析一遍。

更稳的策略是：
- 旧加工版作为迁移基线；
- 原文作为最高证据源；
- 对高风险、高价值、低置信度、旧模型不确定、用户多次纠正过的内容进行选择性原文回查；
- 行为约束要复审，判断哪些是旧模型补丁，哪些仍然必要；
- 新模型能力应先验证，再纳入正式工作流。

这部分未来应形成 model migration review 机制，当前只作为候选需求和 TODO。

## 6. 需求和反馈原文需要长期保存

用户的需求描述、使用体验反馈、上游 Agent 转交的需求等，应保存原文。

原因：
- 避免只保留模型加工版导致语义漂移；
- 支持未来更换模型后重新理解原始意图；
- 支持多 Agent 协作时引用共同约束；
- 支持用户长期回顾早期想法、动机和取舍。

但原文不适合每次完整加载，应通过索引、摘要、候选需求、handoff 和按需回查来降低上下文消耗。

## 7. 第一阶段坚持半自动

当前不追求全自动记忆系统。

第一阶段应保持：
- 用户在 ChatGPT 中继续进行自然语言研究和需求澄清；
- Codex Cloud 负责把确认后的内容小步写入 GitHub 仓库；
- 重要长期变更由用户 review diff 或 PR；
- 自动化、RAG、MCP、GitHub Actions、AGENTS.md、CLAUDE.md、多 Agent 协作和自动查重都延期。
