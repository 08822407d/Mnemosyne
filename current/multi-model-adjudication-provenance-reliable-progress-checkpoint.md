## Purpose

This checkpoint gives the user a reliable point from which to switch the current conversation to the Pro selection and test whether substantive work quality has recovered.

The checkpoint deliberately excludes the earlier Project-internal experimental pair. The reliable input set is the independent-conversation pair plus the maintainer comparison and exact artifact hashes.

## Restart semantics

After this checkpoint becomes effective, a later explicit declaration that the newly switched Pro work is again unreliable and should restart from the last trustworthy point means:

1. preserve all Git history;
2. retain the MNEMOSYNE-145 research records as trusted non-execution-source input;
3. reassess or redo substantive reasoning, prioritization, adjudication, research-route selection, repair design, and execution-source proposals started after this checkpoint;
4. do not rerun the independent Deep Research pair by default;
5. do not rerun Fable GF-STEP-1 through GF-STEP-5 by default;
6. require ordinary user authorization for any repository write, repair, research expansion, or execution-source change.

Purely mechanical post-checkpoint storage may be retained after inspection. Post-checkpoint judgment work should be redone when the user explicitly invokes this restart boundary.
