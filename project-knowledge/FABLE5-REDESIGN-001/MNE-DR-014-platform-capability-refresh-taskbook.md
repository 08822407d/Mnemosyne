## 1. 背景与用途（为什么做这项研究）

一个长期个人项目正在为"AI 新旧对话在同一长期工作上尽可能完美交接（像同一个对话）＋外部持久记忆"做重新设计。它此前关于各 AI 平台能力的研究结论采集于 2026 年 5~7 月，距今 1~3 个月，其中平台功能、配额、模式等信息具有时效性，可能已过期。本研究的结论将直接用于决定：**重新设计中的记忆载体与交接机制可以依赖哪些当前平台功能**。

研究对象是**产品表面的公开事实**（功能、限制、配额、用法），不是学术综述。

## 2. 研究问题（逐题回答）

**Q1 · ChatGPT 记忆与 Projects 现状**：ChatGPT（网页/App）当前的 Memory 机制、Projects 功能（含 project-only memory 及其能否转换）、跨对话引用、自定义指令分层；各订阅计划（Plus/Pro/Business）的差异。

**Q2 · ChatGPT deep research 模式现状**：入口与启动方式；"智能程度/模型"可选项（如 Instant/Thinking/Pro 的三档选择器）各自含义与实际底层模型（官方口径）；Plus 与 Pro 计划的**配额**（每周/每月次数）；单次运行时长与来源数量级；可否连接 MCP/连接器/app 作为研究来源；与 agent mode 的关系；报告的导出格式（Markdown/PDF/Word）；2026 年以来的重要变更（如 legacy 模式移除）。

**Q3 · ChatGPT 的 GitHub 连接与 Codex**：普通对话经 GitHub app/连接器当前的读/写能力（建分支/文件/PR 是否可行、审批卡机制）；Codex（Cloud 与 CLI）现状一句话概览。

**Q4 · Claude 侧现状**：Claude 网页对话的 Projects/记忆功能现状；Claude Code（CLI/VSCode/网页 claude.ai/code）的记忆机制（CLAUDE.md、自动记忆、上下文压缩/compaction、会话恢复 resume、子代理）；当前公开的上下文窗口规格（各计划/模型，含是否有 1M 档）；订阅计划与配额结构。

**Q5 · 原生"跨会话连续性"功能盘点**：两家厂商（及显著的第三方产品）当前有哪些**原生**支持"跨对话/跨会话继续同一工作"的功能（如会话恢复、项目级共享上下文、记忆引用、handoff 类功能）；各自的边界与失败场景。

**Q6 · 对话内模型自识别**：当前是否存在官方机制让 ChatGPT 对话/Codex/Claude 对话可靠获知"自己此刻运行的具体模型"？只采信官方文档或官方人员表述；没有则明确回答"未发现官方机制"。

**Q7 · 上下文窗口与长对话行为**：各产品当前公开的上下文长度数字；对超长对话的处理方式（截断/压缩/性能退化）的官方说明或可靠报道。

**Q8 · 旧结论核对表**：对下列 2026-05~07 时点的旧结论逐条判定【仍成立 / 已过期（给出新事实） / 无法确认】：
1. "ChatGPT 普通对话经 GitHub app 可执行写入类操作（建分支/文件/PR）"（2026-07 观察）；
2. "Deep Research 由 o3 类模型执行"（2026-05 时点）；
3. "Project-only memory 只能在新建 Project 时选择，存量 Project 不能原地转换"（2026-07）；
4. "Deep Research 期间对连接的 app 只执行读取类动作"（2026-07）；
5. "同步的 app 数据可能进入 ChatGPT Memory；断开连接不删除既往对话中的数据"（2026-07）；
6. "GitHub 搜索/同步是相关性导向，不保证完整枚举分支/PR"（2026-07）；
