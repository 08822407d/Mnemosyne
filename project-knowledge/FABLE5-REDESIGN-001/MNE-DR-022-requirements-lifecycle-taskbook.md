## 1. 背景与用途

一个长期个人 AI 项目的第二大目标是"忠实记录用户各阶段的需求原文与构想，并让 agent 真正用得上"。用户需求的现实属性：碎片式、多次累积、跳跃甚至自冲突、可能无理由反复。项目要求系统具备：一致性/可行性分析、知道该做哪些研究、沟通不可行原因与替代、实验验证、**新模型可用时回头重评挂起需求**、反馈连同材料完整记录。本研究采集外部证据，直接用于设计"需求生命周期状态机"并为上述能力定验收标准。相关的记忆层证据（逐字保存优于摘要替代、当前态与过期态分离的基准）项目已另行取得，**本课题聚焦需求/规格工程这一层**，避免重复。

## 2. 研究问题（逐题回答）

**Q1 · 规格驱动开发现状**：spec-driven development（如 GitHub Spec Kit 及同类）2025-2026 的实践现状：spec/plan/tasks 工件化的具体做法、采用度、公开的成功与失败经验；spec 与代码/agent 行为如何保持同步。

**Q2 · 需求演化与当前态管理**：在 AI-agent 或长期软件项目中，需求的版本化、冲突检测、supersession（"哪条作废了哪条"）、当前有效集合（current-state）表示的公开方法与工具；显式状态标注（valid/superseded/deleted/deferred）的实践先例。

**Q3 · 重评触发机制**：有没有"模型升级或环境变化 → 自动/半自动触发需求或设计重审"的公开先例（如 evals-on-model-upgrade、regression review 制度）；怎么组织"挂起需求"的复活审查。

**Q4 · 从模糊意图到验收标准**：把不完整、非专业的人类意图转成可验收标准（acceptance criteria）的方法与工具现状；保留"原话 vs 解释 vs 批准版"分层的实践先例。

**Q5 · 矛盾呈现与人裁决**：需求矛盾如何呈现给 owner 裁决的公开实践（并列对照、diff、裁决记录、裁决可撤销性）；有没有工具把"不调和、留人裁"作为一等流程。

**Q6 · 反馈回流闭环**：使用中反馈（bug/摩擦/新想法）回流为需求变更的追踪链路实践；反馈与其触发材料（上下文、日志）一同保存的做法。

**Q7 · 对照分析**：委托方现行要点（公开信息）：①需求原文逐字保存为 raw 层；②分析/候选层与 owner 批准的执行层分离；③变化走 Git 历史＋人审合并；④矛盾并列不调和、交 owner 裁。基于 Q1~Q6 证据，列出 (a) 业界有而该方案缺的机制；(b) 证据支持或质疑该方案哪些环节；(c) 该方案缺口的最小补法候选。

**Q8 · 度量候选**：如何量化"需求生命周期健康度"（如：需求可追溯率、过期需求误用率、矛盾发现时延、挂起需求复评及时率），给 5~8 个带出处的指标候选。
